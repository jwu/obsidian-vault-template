description: 根据指定日期的笔记元数据与 Git 提交，补写或更新对应日记
argument-hint: "[date]"
---

请根据指定日期涉及的笔记元数据（`created` / `modified`）与 Git 提交，补写或更新该日期的日记。

## 1. 准备

- 如果 `$1` 不为空，目标日期为 `$1`
- 如果 `$1` 为空，目标日期为今天，使用当前系统日期，格式为 `YYYY-MM-DD`
- 目标日记文件：`01-daily-日记/<目标日期>.md`
- 日记不写 `created:` / `modified:`，日期由文件名承载

## 2. 找出当天涉及的笔记（主判据）

日期归属只看笔记元数据，不看 commit 时间。

```bash
git grep --untracked -lE "^created: <目标日期>$" -- '*.md' ':(exclude)01-daily-日记/**'
git grep --untracked -lE "^modified: <目标日期>$" -- '*.md' ':(exclude)01-daily-日记/**'
```

- 第一条是当天新建，第二条是当天修改
- 用 `git grep` 而不是 `grep`：它跳过 `.venv/`、`.obsidian/` 等被忽略的目录
- 排除 `01-daily-日记/`，日记不算自己的关联
- **去重**：`modified` 命中且 `created` 也是当天的，只算新建，不重复算修改（与 `Daily References.base` 两个视图的口径一致）
- 逐份读这两批笔记的内容，理解当天实际发生了什么。**总结的材料来源是笔记本身，不是 Git 提交**
- 两批结果为空时，继续走第 3 步；两边都没材料才告诉我当天无法生成日记

## 3. 用 Git 补齐元数据看不到的改动

元数据只覆盖带 frontmatter 的笔记，下面四类只有 Git 能看到：

- 没有 frontmatter 的文本文件：`.pi/prompts/`、`99-system/bases/`、`99-system/templates/`、`AGENTS.md`、`.scripts/`
- `.obsidian/` 下的配置、插件、主题
- 图片、字体等二进制资产
- 被删除的文件

```bash
git log --since="<目标日期> 00:00" --until="<目标日期> 23:59:59" --date=iso --pretty=format:'%h %ad %s' --reverse
git show --stat --name-status --format=fuller --find-renames <commit>
```

- 只读 `--stat` / `--name-status` 判断改了什么；需要理解具体内容时再读 patch，不要对每个提交都展开全文
- **commit 时间不参与日期归属判断**。元数据日期与 commit 日期不一致时，一律以元数据为准
- 当天没有 commit 很正常，不代表没有工作；不要因为缺提交就略过当天的笔记
- 有提交但对应笔记的 `modified` 不是当天，说明那批改动属于别的日子，不要在当天日记里展开

## 4. 书写日记

直接编辑目标文件，禁止使用 `obsidian-cli` 的 `daily:append` 和 `daily:prepend`。

- 文件已存在：用 `edit` 更新
- 文件不存在：先确认没有同名或相近日期日记，再用 `obsidian vault=work create name="<目标日期>" path="01-daily-日记"` 创建，然后用 `edit` 写入

结构固定为三段，不要新增小节。

### `## 日志`

分两块：先叙事，末尾是当天涉及的笔记清单。

#### 叙事（≤600 字）

- 一级主事务独立成段，**不要用列表**
- 事务与事务之间空一行
- 主事务下的子事务才用 `-` 列表
- 每个主事务只写真实做了什么、为什么重要、形成了什么判断或去向
- 不写实现细节，细节留在档案和知识库里
- 同类事项合并成一个主事务，不要逐文件罗列
- 某个事务已在前一天日记展开过时，当天只写收尾并链回前一天
- **硬配额**：叙事正文合计 ≤600 字（不含列表缩进、URL、下方清单），每个主事务 ≤3 句
- 超配额时按此顺序砍：意义升华 → 背景铺垫 → 举例罗列，只留「发生了什么 + 判断/去向」
- 判断不能丢，但必须压成一句；一句话放不下的深度内容属于档案、调研笔记或 `98-ai-output-ai输出/`，不属于日记
- 展开到什么程度跟随当天材料的实际分量，不为了凑长度扩写，也不为了配额丢掉判断本身
- **与清单去重**：清单写完后回查叙事，逐句判断有没有清单之外的增量
    - 某句只是把清单里的事实复述一遍 → 删掉这句
    - 某句含清单没有的判断、背景、对比、纠错过程或后续去向 → 保留
    - 典型要删：「新建 X 应用档案：<与清单条目几乎逐字相同的描述>」
    - 典型要留：「X 一开始误建在技术档案里，随后转到应用」（建档过程中的纠错）
    - 同一件事不在两处各写一遍

#### 涉及笔记清单（不计入 600 字配额）

叙事之后空一行，用**加粗行**做标签，**不要用 heading**，否则破坏三段结构。

```md
**今日新建**
- [[笔记名]] — 一句话说明
- [[笔记名]] — 一句话说明

**今日修改**
- [[笔记名]] — 一句话说明
```

- 每篇一条，固定格式 `- [[wikilink]] — 一句话说明`，分隔符用 `—`
- 一句话说明写**实质改动**：新增章节、修正判断、补充数据、换来什么结论，不要复述笔记标题
- **分工**：清单只讲「这篇是什么 / 改了什么」，判断题、背景、对比与后续去向留给叙事（具体去重方法见上方「与清单去重」），两边不重复同一件事
- `created` 当天命中的只出现在「今日新建」，不在「今日修改」重复
- **机械修改不逐篇列**：只改 `modified`、只同步 wikilink、只调整格式这一类，在清单末尾合成一行，写清数量与动作，不逐篇展开（如 `- 另 61 篇笔记 — 批量统一正文链接为尖括号自动链接写法`）。不要把它们彻底省略——否则 AI 读日记时看不出那天碰过那批笔记。叙事里能带一句就带一句
- 某批为空就整块省略；两批都为空时不写清单
- 清单里的 wikilink 同样按第 5 步检查，库中无对应笔记的保留纯文本

### `## 待办`

- `- [ ]` 开头
- 不要改写，除非当天材料明确显示待办状态变化

### `## 关联笔记`

- 保持模板里的两个 Bases 嵌入不动

## 5. 写入后检查

- 逐句扫描日记中提到的所有实体（叙事段落和涉及笔记清单都要扫：笔记名、项目名、技术名、人名、文档名等），检查库中是否已有对应笔记：
    - 有 → 使用 `[[wikilink]]`；如果当天发生重命名，确认最新文件名后再写，不要用旧名
    - 没有 → 保留纯文本
- 跑一次 `uv run python .scripts/touch_modified.py --date <目标日期> <改过的笔记相对路径...>`

**`--date` 必须显式写成 `<目标日期>`。** 脚本默认用今天，补写历史日记时会把 `modified` 全部刷成今天，导致这些事务在第二天被重复记进当天日记。日记自身没有 `modified` 字段，脚本会自动跳过。

## 6. 完成后汇报

用简洁中文告诉我：

- 更新了哪个日记文件
- 覆盖了哪些主事务
- 清单里记了几篇新建、几篇修改，哪些命中的笔记被判定为机械修改而归入叙事
- 哪些材料来源不明确，或需要我确认
