---
description: 把一条内容快速记录到今天日记的「日志」区
argument-hint: "<链接、一句话或一段描述>"
---

把 `$ARGUMENTS` 作为一条记录，写进今天日记的 `## 日志`。

## 1. 目标文件

- 日期取当前系统日期，格式 `YYYY-MM-DD`，目标文件 `01-daily-日记/<日期>.md`
- 文件不存在时，先确认没有同名或相近日期日记，再用 `obsidian vault=work create name="<日期>" path="01-daily-日记"` 创建，然后用 `edit` 写入
- 禁止使用 `obsidian-cli` 的 `daily:append` 和 `daily:prepend`
- 日记不写 `created:` / `modified:`

## 2. 理解内容

- 内容是 URL → 用 `webfetch` 读，抓清楚它是什么、解决什么问题
- 内容是纯文字 → 直接理解
- 读取失败或读不出要点时，不要编造，只记录我给的原始描述，并说明没读到内容

## 3. 写入

- 只动 `## 日志`，`## 待办` 与 `## 关联笔记` 一律不动
- 日志区只有模板占位句（如「美好的一天，从这里开始」）→ 用这段替换它
- 日志区已有实质内容 → 追加到末尾，与上文空一行
- 与已有段落讲的是同一件事 → 合并进那一段，不在两处各写一遍
- 篇幅固定为一段，总长 ≤80 字，通常两句：一句是什么 + 一句判断（价值、位置或去向）
- 语气要像日记：口语化、第一人称，对着自己说话，不写分析报告
    - 起句可用「今天看到……」「翻到……」，判断写成自己的感受，如「感觉对我做 xxx 挺有用」「先放着，回头试试」
    - 「是什么」只用一两个词点明（如「一个 agent 视频创作系统」），不报功能清单
    - 不写「它的看点不是 X，而是 Y」这类对照分析句，也不写实现细节、背景铺垫、举例罗列
- 正例：`Hypit：<https://github.com/hypit-ai/hypit>，一个 agent 视频创作系统，丢一条视频就能克隆整条工作流。感觉对我做 aigc 批量出片有用，想找时间试跑一次。`
- 反例：`它的看点不是「复刻爆款」，而是把视频生产变成 agent 能直接读写的源码，可以拿现成案例试跑后再判断是否接进 xxx 流程。`（分析腔、术语多、没有自己的语气）
- 一级记录独立成段，不要用列表；只有该记录下确有子项时才用 `-`
- 中文冒号后接链接用尖括号包住：`名称：<https://...>`

## 4. 写入后检查

- 扫一遍提到的实体（工具名、项目名、笔记名、人名），库中已有对应笔记就用 `[[wikilink]]`，没有就保留纯文本
- 只做记录：不建档、不新建其他笔记、不改 `10-todo-待办/`，即使内容明显值得归档也不擅自动手
- 日记没有 `modified` 字段，不跑 `.scripts/touch_modified.py`

## 5. 汇报

一句话说明记了哪天、写的是什么判断，不复述日记原文。
