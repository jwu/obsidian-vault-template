# Book Archiving

为本项目中的书籍建立或完善档案，输出到 `80-archive-档案库/Book-书籍/`，并尽量保持与现有书籍笔记一致的结构、语气与信息密度。

## When to use

在以下情况使用本技能：
- 用户要求为某本书建立档案
- 用户提供一个书名、作者名、出版社链接或 ISBN，希望整理成标准书籍笔记
- 用户要求补充某本书的目录、作者背景、评价或购买渠道
- 用户要求对某本书按 `1~7` 制打分

## References

开始前优先读取这些参考材料：
- `../../../99-system/templates/Book Template.md`

如需对齐现有风格，可查看 `80-archive-档案库/Book-书籍/` 下已有笔记，例如：
- `../../../80-archive-档案库/Book-书籍/Game Anim.md`
- `../../../80-archive-档案库/Book-书籍/Game Engine Architecture.md`

评分规则参考：
- `../../../99-system/rating.md`（`1~7` 整数制）

## Output

书籍档案统一放在：
- `80-archive-档案库/Book-书籍/`

默认要求：
- 文件名使用书籍常用名
- 笔记需包含 `created:` 属性
- 优先沿用 `[[Book Template]]` 的结构
- 作者若库内已有对应人物笔记，使用 wikilink，否则用纯文本

## Rules

- 默认使用简洁中文
- 保留事实，不臆测
- 优先小步补充，不大改原文
- 如果信息不确定，宁可留空，也不要强填
- 编辑 Markdown 内容时保持 Obsidian 兼容
- 引用文件夹时不要使用 `[[wikilink]]`，统一使用 `文件夹名/` 形式
- 若需创建、移动、重命名书籍笔记，遵循项目要求，使用 `obsidian vault=work ...` 完成
- 书籍评分统一使用 `1~7` 整数制，依据 `99-system/rating.md`
- 笔记内容中提及的技术、人物、概念等，若库内已有对应笔记则使用 wikilink，若是外部资源则使用外部链接，尽量让内容可导航

## Workflow

### 1. 确认输入

用户可能提供：
- 一个书名（最常见，如「Game Anim」「Game Engine Architecture」）
- 书名 + 作者名
- 书名 + ISBN
- 书名 + 出版社链接或 Amazon 链接
- 书名 + 领域描述（如「那本游戏引擎的权威书」）

目标是先确认"要归档的是哪本书"。

- 如果用户提供的信息已经足够唯一定位到该书，则继续下一步
- 如果信息过少、存在重名，或无法确认是否为目标书籍，则先向用户确认
- 在书籍身份未确认前，不要擅自创建笔记或合并到现有笔记

### 2. 确认是否已有笔记

先搜索 `80-archive-档案库/Book-书籍/` 中是否已有同名或近似书籍笔记。

- 如果已有：在原笔记上补充
- 如果没有：基于模板新建
- 如果出现同名或疑似重名书籍：先暂停并向用户确认，不要擅自合并

### 3. 信息收集与内容整理

#### 基本信息

优先从以下来源获取：
- 出版社官网（Routledge、CRC Press、O'Reilly 等）
- Amazon 商品页面
- 作者个人网站（通常有专门的 book 页面）
- 豆瓣读书

#### 封面图

封面图来源优先级：
1. 出版社官网商品页
2. 作者个人网站的 book 页面
3. Amazon 商品页面
4. 若以上均无法获取，可省略

封面图通过 `cover` 属性存储 URL，正文内通过 `![[书名#cover|200]]` 或 `![[no-image-placeholder.svg|300]]` 展示。

#### 目录主题

从以下来源获取目录：
- 出版社官网的商品详情页（通常有「Table of Contents」）
- Amazon 的「Look Inside」功能
- 书籍前言/目录页（如有 PDF 预览）
- 作者网站的 book 页面

目录格式：
- 每章一行，格式 `Chapter N: Title — 中文简述`
- 如果章节目录很详细（如有多级子节），优先列出第一级章节
- 若无法获取完整目录，可根据书籍简介和已有信息整理主题列表

#### 评价

评价来源：
- 出版社官网的 Editorial Reviews / Endorsements
- Amazon 的读者评价和 Editorial Reviews
- 知名技术博客或社区的推荐
- 若涉及个人评分，使用 `1~7` 制

#### 其他信息

在"其他"栏目中补充：
- **购买渠道**：Amazon、出版社官网、其他正规渠道
- **版次**：各版本出版年份、ISBN 及主要变化
- **相关资料**：书籍官网、配套资源（代码仓库、示例下载、视频教程）、作者博客或文章

### 4. 生产档案文件

#### 建立 frontmatter 属性

优先整理这些属性：

```yaml
---
created: YYYY-MM-DD
template: "[[Book Template]]"
cover:
author:
genre:
website:
release date:
rating:
aliases:
---
```

填写规则：
- `cover`：封面图 URL，优先用出版社或作者官网的高清图片
- `author`：作者名，若库内已有对应人物笔记则用 wikilink（如 `"[[Jonathan Cooper]]"`），否则用纯文本（如 `"Jason Gregory"`）
    - 先搜索 `80-archive-档案库/People-人物/` 中是否已有对应人物笔记
    - 多作者时用 YAML 数组：`["[[作者1]]", "作者2"]`
- `genre`：书籍所属领域/类型，用 ` / ` 分隔多个领域，如 `游戏引擎 / 计算机图形学 / 软件工程`
- `website`：书籍专属官网或作者 book 页面
- `release date`：发行日期（YYYY-MM-DD），优先记录当前版本
- `rating`：按 `1~7` 整数制评分；未充分了解时可暂空
- `aliases`：仅在确有常见别名、译名、缩写时填写
- 未找到或无法确认的字段，直接省略，不要保留空字段
- 仅保留已确认且对后续检索、补充有价值的属性

#### 使用统一格式写入正文

正文结构严格遵循 `[[Book Template]]`：

```md
![[no-image-placeholder.svg|300]]

## 简介

简单介绍这本书

## 目录主题

- Chapter 1 ...
- Chapter 2 ...

## 评价

我的评价、社群评价、人物评价

## 其他

包括主要购买渠道、再版情况、相关资料等
```

格式要求：
- 封面：`![[书名#cover|200]]`（使用 Obsidian wikilink embed 引用 frontmatter 中的 cover 属性），若 cover 为空则用 `![[no-image-placeholder.svg|300]]`
- 简介：说明书名全称、版本与年份、定位；列举作者背景与代表作品；说明版本更新内容；提及出版方
- 目录主题：用无序列表，每章一行，格式 `Chapter N: Title — 中文简述`；若无法获取章节号，用主题描述
- 评价：用无序列表，包括社群评价、适用对象、个人评分（如已填写 `rating`）
- 其他：细分为「购买」「版次」「相关资料」三个子节（用三级标题 `###`）
    - 购买：列出购买渠道链接，每项一行
    - 版次：按时间降序列出各版本，格式 `第 N 版：YYYY 年，ISBN xxx，主要变化`
    - 相关资料：官网、配套资源（代码、教程、视频）链接

#### 补全正文中的链接

正文写完后，必须逐项扫描「简介」「目录主题」「评价」「其他」中提到的所有技术、人物、概念名称，逐个判断：

1. 在 `80-archive-档案库/` 中搜索是否已有对应笔记 → 有则用 `[[wikilink]]`
2. 没有笔记但存在明确的链接（官网、仓库、文章）→ 用 Markdown 外部链接 `[名称](URL)`
3. 上述两项都没有 → 保留纯文本

此步骤是强制检查项，不可跳过。

## Ambiguity handling

遇到以下情况时，优先保守处理：
- 无法确认是否为同一本书（重名或译名混乱）：先向用户确认
- 多个来源信息冲突（如不同平台目录不同）：优先采用出版社官网信息；若仍无法判断，则暂不写入
- 书籍有多个版本：优先记录最新版本信息，在"版次"中列出历史版本
- 无法确认发行日期：不要伪造日期，可暂缓写入或标注大致年份
- 某栏目暂无可靠信息：可保留空节或不写入该节
- 评分不确定：宁可不评分，也不要随意打分

## Quality bar

- 优先记录"长期有价值"的书籍定位与内容结构，而不是堆链接
- 简介应让读者快速判断"这本书讲什么、适合谁读"
- 目录主题应有中文简述帮助理解，而非仅贴英文标题
- 评价应有实际引用来源（如"被 XX 推荐"），而非泛泛的"好评"
- 其他中的版次信息应有各版本的实际差异，而非仅列年份
- 如果条目很多，先选最能代表此书籍的核心信息
- 若发现已有内容结构混乱，先轻量整理，再补充信息
- 输出应便于后续持续补充，而不是一次性塞满

## Delivery

完成后，简要说明：
- 新建了还是更新了哪一篇书籍笔记
- 补充了哪些信息，如封面、作者背景、目录、评价、购买渠道、版次
- 哪些信息仍缺失或待确认（如完整目录、ISBN、评分等）
- 若已评分，简要说明评分依据
